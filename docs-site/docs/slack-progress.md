# Slack 階段定期回報

每個正在執行的階段會在原討論串建立一則由系統代報的狀態卡，標明任務編號、角色與節點、
本次階段耗時與狀態更新時間（台北時間）；預設每 300 秒更新同一則訊息。
`AI_TEAM_PROGRESS_INTERVAL_SECONDS` 可調整間隔，最小 30 秒。

配置式階段與唯讀對話的卡片會顯示 runtime、模型與已指定的 reasoningEffort，並標示為「要求值」；
未指定的欄位顯示 CLI 預設。Codex JSONL 事件不提供實際模型，所以卡片不能當成供應商實際模型的證明。

涵蓋配置式流程、角色唯讀對話、legacy 階段（含新 session 接手）及系統獨立驗證。
配置式流程的卡片帶有「中斷這一輪」按鈕，只停下目前這一輪、不中止任務；
與「中止任務」的差異見 [QA 受阻後的 PM 處理](pm-triage.md#中斷這一輪-vs-中止任務)。

## 卡片代表什麼、不代表什麼

此卡只表示呼叫尚未返回，**不是** CLI process 健康證明、工具活動摘要或完成百分比。
完成、失敗及額度例外都會停止該卡心跳；偵測到資料庫任務不再執行或被刪除時亦停止。
結束時卡片改為「本次階段定期回報已結束」並移除按鈕，不宣稱成功；
正式結果仍以主狀態、角色報告及驗收閘門為準。

## 失敗處理

通知失敗不改變任務結果。建立訊息失敗會在下一輪重試；更新失敗由 Slack 通知器記錄。
每個階段使用獨立卡片，避免覆蓋人工核准按鈕或下一角色狀態。
同一張卡片的結束與定期更新互斥，結束後不再發送舊的執行中狀態。
